# Дизайн API Gateway для DSP-интеграции

API Gateway – единая точка входа для всех внешних участников: DSP-партнёров, рекламодателей и пользователей. Снаружи принимает HTTPS, внутрь передаёт по gRPC.

## Выбор шлюза: Envoy

Всё, что нужно от шлюза, в Envoy есть из коробки: преобразование HTTPS/JSON → gRPC (`grpc_json_transcoder`), повторы с экспоненциальным backoff и джиттером, Circuit Breaker, аутентификация (JWT, внешняя авторизация), rate limiting, метрики и трассировка.

Рассматривался NGINX + Lua: он проще в настройке, но большую часть этих функций пришлось бы писать и сопровождать самим на Lua. Для AdScale дешевле освоить настройку Envoy, чем поддерживать собственный код; SRE будем набирать сразу под эту технологию.

## 1. Маршрутизация запросов на ставки

| Откуда | Куда | Протокол снаружи → внутри |
|---|---|---|
| DSP-партнёры: bid request | Bidding Service | HTTPS / OpenRTB (JSON) → gRPC |
| Пользователи: показы и клики | Delivery Service | HTTPS → gRPC |
| Рекламодатели | Advertiser Dashboard | HTTPS → gRPC |

JSON в формате OpenRTB шлюз преобразует в gRPC фильтром `grpc_json_transcoder`. Если Bidding Service возвращает no-bid, шлюз отвечает партнёру HTTP 204 No Content в пределах `tmax`.

## 2. Ограничение частоты запросов (rate limiting)

Rate limiting применяется к запросам пользователей: авторизация им не нужна, но нужна защита от DDoS-атак.

## 3. Аутентификация

Шлюз аутентифицирует рекламодателей и внешние системы, включая DSP-партнёров, – для безопасности и надёжности. В Envoy для этого есть встроенные фильтры: JWT (`jwt_authn`) и внешняя авторизация (`ext_authz`).

## 4. Автоматический размыкатель (Circuit Breaker)

Шлюз применяет Circuit Breaker и повторы с экспоненциальным backoff и джиттером к вызовам внутренних сервисов.

- Показы и клики пользователей и запросы рекламодателей повторяются, чтобы не потерять важный для бизнеса показ или клик. При повторе шлюз отправляет тот же идентификатор запроса, поэтому деньги не спишутся дважды.
- Bid requests не повторяются: опоздавший ответ партнёру бесполезен. Если цепь к Bidding Service разомкнута, шлюз отвечает партнёру no-bid (HTTP 204): лучше ответить, чем молчать.

## 5. Мониторинг времени отклика

Шлюз обеспечивает прослеживаемость состояния системы: Envoy собирает метрики и трассировку запросов из коробки. Время ответа на bid request отслеживается по требованиям из драйверов: P95 не больше 100 ms, для нового DSP-партнёра – не больше 80 ms.
