# Архитектура потоковой обработки событий (Kafka)

Delivery Service публикует показы и клики в Kafka. Их асинхронно читают двое: Statistics пишет события в PostgreSQL, ClickHouse для Analytics забирает их напрямую, отдельной группой потребителей. Запись событий не замедляет ответы на bid request.

Kafka хранит события: если показ или клик не записался, событие можно перечитать из топика. Повторно прочитанное событие не посчитается дважды: у каждого показа и клика свой идентификатор, Statistics пропускает уже записанные.

## 1. Топики Kafka

| Топик | Что в нём | Кто публикует |
|---|---|---|
| `impressions` | показы | Delivery Service |
| `clicks` | клики | Delivery Service |

Показы и клики разделены по топикам: они обрабатываются и учитываются по-разному.

Ключ партиционирования – id события. События распределяются по партициям равномерно, а повтор одного и того же события попадает в ту же партицию.

## 2. Схема событий: Avro или JSON

Формат – JSON. Avro потребовал бы Schema Registry – ещё один компонент, а инфраструктура и DevOps уже нагружены.

Поля события показа или клика:

| Поле | Что это |
|---|---|
| `event_id` | id события, ключ партиционирования и защита от дублей |
| `event_time` | время события |
| `campaign_id` | id кампании |
| `creative_id` | id креатива |
| `dsp_partner_id` | id DSP-партнёра, от которого пришёл bid request |
| `site` | сайт или приложение, где был показ |
| `price` | цена показа из выигравшей ставки |
| `user` | данные о пользователе, по необходимости |

```json
{
  "event_id": "7f3c9a2e-...",
  "event_time": "2026-09-28T12:00:00.123Z",
  "campaign_id": "cmp-1024",
  "creative_id": "crt-77",
  "dsp_partner_id": "dsp-new",
  "site": "news.example.com",
  "price": 0.12,
  "user": { "geo": "RU-MOW", "device": "ios" }
}
```

## 3. Группы потребителей

| Группа | Кто читает | Топики | Куда пишет |
|---|---|---|---|
| `statistics` | Statistics Service | `impressions`, `clicks` | PostgreSQL |
| `analytics` | ClickHouse (движок Kafka) | `impressions`, `clicks` | ClickHouse |

Группы независимы: каждая читает все события в своём темпе, и падение одной не мешает другой.

## 4. Политика хранения

События в топиках `impressions` и `clicks` хранятся 7 дней (`log.retention.hours=168`). Этого хватает, чтобы пережить простой Statistics или ClickHouse, например на выходных, и затем дочитать все события.
