## Ключевые решения

- Statistics – PostgreSQL (OLTP), Analytics – ClickHouse (OLAP); Statistics остаётся надёжным учётом событий без дублей, по нему списываются деньги.
- Показы шардируются хешем `event_id`: проверка дубля всегда попадает в один шард.
- Кеш: инвалидация по событию плюс TTL с джиттером; остаток оплаченных показов не кешируется – Bidding опирается на статус кампании.
- Kafka: топики `impressions` и `clicks`, JSON, две независимые группы потребителей, хранение 7 дней.
- RPO 0 для Financial, Statistics и Analytics; синхронная реплика у Financial; бэкапы по схеме GFS с WAL.
- Все сервисы в контейнерах под Kubernetes.
